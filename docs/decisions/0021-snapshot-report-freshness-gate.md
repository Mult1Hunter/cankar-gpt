# ADR 0021 - local freshness gate for snapshot reports

**Status:** accepted, 2026-07-26

## Context

`registry/reports/` holds two classes of generated file (`cankar/core/reports.py`).
The `snapshot=False` class rebuilds byte-identically from committed inputs and CI
guards it. The `snapshot=True` class is computed from gitignored `data/`, which CI
never has, so it was knowingly left unguarded - until it bit. The ADR 0014
re-merge left `token-stats.md` claiming 126,355 docs against `merge.md`'s 126,352,
and `tokenizer-eval.md` still carrying the pre-re-merge sha `cdfea262`. Both sat
in a public repo; the first was caught by hand, the second only by the sweep the
first triggered. Meanwhile CLAUDE.md called the whole directory "drift-checked",
true of one class and read as true of both. Four snapshot reports already record
the corpus sha they were built from. Nobody compared it to anything.

## Decision

A local test (`tests/structure/test_report_freshness.py`) hashes the merged corpus
and fails on any snapshot report whose recorded sha differs, naming the report and
its own regeneration command. It skips when the corpus is absent - the normal
state in CI and fresh clones. Parsing lives in `cankar/core/reports.py`. A second
test pins the set of corpus-derived reports carrying no sha, so a new unstamped
report cannot slip in.

## Rationale

- **The test suite, not a hook:** it already runs locally and skips where data is
  missing. A repo-local `pre-push` would be dead anyway - a global `core.hooksPath`
  shadows repo hooks and chains only `pre-commit`/`commit-msg`.
- **Compare the stamp, do not regenerate:** one sha256 over 503MB is ~0.3s;
  rebuilding every snapshot report is minutes.
- **Anchored on "corpus" + `sha256` on one line,** so a report stamping another
  artifact's hash is never compared, and `merge.md` / `corpus-quality.md` - whose
  `GENERATED by` command contains "corpus" - still read as unstamped. Both are
  regression fixtures.
- **Malformed reads as unstamped, never fresh.**
- **Calibrated on a real positive (ADR 0006):** written against a tree where
  `tokenizer-eval.md` was genuinely stale and required to fail first. The four
  writers' real phrasings are fixtures, including `chunk.py`'s line break between
  label and sha, which defeats any per-line regex.

## Consequences

- `tokenizer-eval.md` regenerated here: Cankar slice 249 -> 246, matching ADR
  0014's stated consequence. The v8192 selection and rationale are preserved;
  fertility is unchanged (1.766), so the choice still holds.
- CLAUDE.md's `registry/reports/` claim is narrowed to what is true.
- Three reports still carry no sha and are pinned in an allowlist; stamping them
  touches three writers, deferred under rule of two and visible rather than implied.
- Lesson (the ratchet): a rule that covers *part* of a directory reads as covering
  all of it. Scope the claim, or gate the remainder.
